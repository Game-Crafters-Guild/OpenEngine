title: Navigation surface
description: Where navigation agents can walk, baked from the scene's terrain, static colliders, and meshes, saved with the scene, rebaked tile by tile where the scene changes, with its settings, the bake notice, and the C++ and C# calls.
---

A **Navigation Surface** is where navigation agents can walk. It is baked from what is already in the scene: the terrain, the collider shapes of static physics bodies, and the meshes of mesh renderers inside its bounds. The bake needs no physics world, so a surface bakes in the editor as soon as you add it, and again in Play and in a game.

## Make a surface

:::steps

1. Select an entity (an empty one is fine) and choose **Add Component > Navigation > Navigation Surface**. With **Fit Bounds** on, the surface covers the terrain's footprint, or everything it bakes from when the scene has no terrain.
2. Set the agent: **Agent Radius**, **Agent Height**, **Max Slope**, and **Step Height** describe the character that walks the surface.
3. The surface bakes on its own the first time. After you change the scene or a setting, press **Bake** on the notice at the bottom of the component.
4. Read the notice: it says what the bake is doing or what it made. While the entity is selected, the Scene View tints the walkable surface blue and outlines its edge in yellow, in both modes. An outlined hole is ground an agent cannot walk.

:::

## Settings

| Setting | Default | What it does |
|---|---|---|
| Mode | Mesh | **Mesh**: a navigation mesh agents walk anywhere their size fits. **Grid**: one height and one walkable flag per cell, for per-cell costs, cell reservations, hex cells, and the grid cost brush. Switching the mode moves Cell Size between 0.5 m (mesh) and 1 m (grid) when it is still at the other mode's value. |
| Agent Radius | 0.5 m | The surface stays this far from walls. Gaps narrower than twice it close. |
| Agent Height | 1.8 m | Space under an overhang lower than this is not walkable. |
| Max Slope | 45° | Ground steeper than this is not walkable. |
| Step Height | 0.4 m | The least rise between neighboring cells an agent climbs. Max Slope can allow more (see [Slopes and steps](#settings)). |
| Cell Size | 0.5 m | The resolution. A mesh is cut into tiles of 64 cells (32 m at 0.5 m) and spans at most 64 x 64 tiles (2,048 m on a side at 0.5 m). A grid has one cell of this size. The caption under the value gives the tile or cell count the current settings make, before a bake. Smaller follows the ground more closely and takes longer to bake. |
| Fit Bounds | on | On: Center and Extent show the fitted box, read only. Off: the surface covers the box of half size **Extent** around **Center**, measured from the entity's position. |
| Authored Cells | none | Grid only: the costs and blocked cells painted with the navigation grid brush (a `.navgrid` asset). Applied when its size matches the grid. |
| Baked Data | none | Mesh only: the baked tiles saved with the scene (a `.navsurface` asset). Saving the scene writes it and fills this field; see [Saved tiles](#saved-tiles). |

:::note[Slopes and steps]

A surface sampled in cells cannot tell a slope from a staircase of cell-sized steps, so the rise an agent climbs between neighboring cells is the larger of Step Height and the rise of a Max Slope slope over the distance between them: `max(Step Height, distance × tan(Max Slope))`, on a mesh and a grid alike. Wherever a cell is wide enough for that slope rise to exceed Step Height, any step up to the slope rise is walkable too. At the mesh defaults (0.5 m cells, 45°) a rise of up to 0.5 m between neighboring cells is walkable; on a grid at its defaults (1 m cells, 45°) up to 1 m between side neighbors and 1.41 m between diagonal ones. Step Height limits steps only where it exceeds the slope rise: on a mesh's stairs, or on a grid with smaller cells. Lower Cell Size where low walls must block.

On a grid, a wall, a fence, or the side of a box blocks every cell it stands in, wherever in the cell it stands, when it rises higher than the climb between side neighbors (1 m at the grid defaults) and starts lower than Agent Height above the cell's ground. A 4 m wall between two columns of cell centers blocks both columns. A 0.6 m wall is walkable, on a column of centers or between two. A face with no thickness that lies exactly on a grid line belongs to neither cell and blocks nothing: give a fence some thickness.

:::

## What the surface bakes

- **Terrain**: the first enabled planar terrain's heights, after its modifiers. A terrain tile that has not streamed in holds the bake until it arrives. Planet terrains are not baked.
- **Collider shapes**: box, sphere, capsule, and plane colliders on **Static** physics bodies. Triggers are not baked.
- **Mesh renderers**: each renderer's own mesh, models and primitives alike, as its [Navigation Source](#leave-out-or-bring-in-a-mesh) policy admits it. A model that is still loading holds the bake until it arrives. One that cannot be loaded is left out, with a warning in the log.

By default, dynamic and kinematic bodies and navigation agents are not part of the surface, nor are the meshes under them: they move.

## Leave out or bring in a mesh

By default the surface bakes every mesh that does not move, so a flower, a reed, or a leaf card with no collider changes where agents walk. Add **Add Component > Navigation > Navigation Source** to the entity and pick a **Policy**:

| Policy | The entity's mesh |
|---|---|
| Auto | Baked when neither the entity nor any of its parents moves: none has a navigation agent, or a physics body that is not Static. This is the rule with no Navigation Source. |
| Include | Always baked, where it stands when the bake runs, also on a kinematic or dynamic body or a navigation agent. The surface does not follow it when it moves. A child that inherits Include and moves on its own, such as a crew member on an included deck, is left out unless it sets Include itself. |
| Exclude | Never baked. Colliders are separate sources: a Static collider on the same entity or a child is still baked. |

The policy covers the entity's own mesh and the meshes of its children: the children of a blueprint, and the submesh entities a model makes under the entity that shows it. A child with its own Navigation Source, Auto included, follows its own policy instead. Saving the scene or the blueprint keeps the policy.

:::tip[A tree agents walk under]

Put a Navigation Source with **Exclude** on the tree's root and keep the trunk's Static collider. The crown and any leaves under the root leave the bake, so the ground under the crown is walkable, and the trunk's collider stays an obstacle. Mesh-only architecture, such as stairs and platforms with no collider, needs no Navigation Source: Auto bakes it. Under an excluded root, give it **Include**.

:::

To see what a bake reads, ask the editor's debug port: `node mcp/ge.mjs get_navigation_sources` lists every collider and mesh inside the surface's bounds, with its kind and, for a mesh, the policy that admitted it. From C++, `GameEngine::Navigation::ListBakeSources(world, surfaceEntity, sources)` in `PathfindingECS/Navigation.h` fills the same list. Both gather the scene: call them when it changes, not every frame.

## Saved tiles

Saving the scene writes each baked mesh surface's tiles to a `.navsurface` file beside the scene and points the surface's **Baked Data** at it. When the scene opens again, in the editor or in a game, the surface loads its tiles from the file instead of baking them, as long as the file was made for the surface's Cell Size, agent, and bounds. A file made for other settings or bounds is not used: the surface bakes, and the next save writes the file again. Saving a scene whose surface has not changed leaves its file as it is.

Each tile in the file carries a hash of what it was built from: the terrain heights under it and the shapes of the colliders, meshes, and carving obstacles that overlap it. Counters, entity handles, and load order never feed the hash, so an unchanged scene reopens with every tile current. A tile whose ground changed since the save (a mesh moved, a terrain edited) loads all the same and is **stale**: agents use it until the surface rebakes it, which it does on its own. The notice counts the stale tiles and names one.

The file holds one format version. A `.navsurface` of another version does not load, with an error in the log, and the surface bakes instead.

## Rebaking what changed

Once a mesh surface is baked, it rebakes only the tiles that change, a few each frame:

- **A terrain edit**: a sculpt, a modifier, or a script that changes the heightfield rebakes the tiles over the changed samples.
- **A carving obstacle**: a `NavigationObstacle` component with `Carve` set, from code or in the scene file (`NavigationObstacle.carve = true`), cuts a vertical cylinder of its Radius out of the surface, covering the ground within its Height above and below its position. Adding, moving, removing, or disabling it rebakes the tiles under it. Agents keep their radius from the cut, as from a wall. Without Carve, a mesh surface ignores the obstacle.
- **MarkDirty**: geometry a game places or moves that the surface does not watch, such as a built wall made of meshes, is rebaked when the game calls `MarkDirty` over its box (see [From C++ and C#](#from-c-and-c)).
- **Stale tiles** loaded from Baked Data.

A dirty tile is rebuilt only when its content changed: its hash (see [Saved tiles](#saved-tiles)) is computed again, and a tile whose hash matches stays as it is. Each frame takes at most 8 dirty tiles, oldest first; the rest wait their turn, so a large change spreads over several frames. A `MarkDirty` box also makes the surface read the scene's colliders and meshes again, once, on the frame it takes the box; a carving obstacle is read again only on the frame it is added, changed, moved, or removed. Between reads, a baked mesh surface keeps in memory the collider and mesh triangles it last read, about as much as the scene's static geometry, so a rebake reads nothing from the scene. Every tile keeps working until its rebuilt version replaces it. An agent whose path crosses a replaced tile solves its path again and keeps walking the old one until the new path is ready. **Bake** rebuilds the whole surface at once.

## Reading the notice

| The notice says | Meaning |
|---|---|
| `Baking: 212 of 1,024 tiles` | The mesh is being built tile by tile in the background. Tiles already built are in use. |
| `Baked: 1,024 tiles, 1,948 polygons, 0.5 MiB, version 1036` | Done. On a mesh, the version counts the tiles put into the surface by bakes, loads, and rebakes, so it changes whenever a tile does. On a grid it counts bakes. |
| `Baked: … version 1036. Rebaking: 12 tiles` | Tiles a terrain edit, a carving obstacle, or MarkDirty touched are waiting or being rebuilt. The old tiles are in use until then. |
| `Baked: … version 1036. Stale: 3 tiles, (2, 5) among them, whose ground changed since the bake: rebaking` | Tiles loaded from Baked Data were built from other ground. They are in use and rebake on their own. |
| `Waiting for: the baked data (.navsurface) to load` | The saved tiles are loading. The surface uses them once they have. |
| `Out of date: the settings changed since the last bake (1,024 tiles). Bake to apply.` | A setting changed after the last bake. The surface still holds that bake until Bake is pressed. After a Mode change the text names the mode of the bake it holds. |
| `Waiting for: terrain tile (3, 7) is not resident` | Part of the bounds lies on a terrain tile that has not streamed in. The bake continues once it has. |
| `Waiting for: model Rock is still loading` | A mesh renderer shows a model that has not loaded yet. The bake starts once it has. |
| `Failed: no geometry inside the bounds; …` | Nothing the surface bakes from is inside its bounds. Move the bounds, or add a terrain, a static collider, or a mesh. |
| `Failed: the bounds need 4,761 tiles and a mesh surface spans at most 64 x 64 tiles (2,048 m on a side at this Cell Size): …` | A mesh surface wider than 64 tiles on a side is refused. Shrink the bounds to 2,048 m or less, or raise Cell Size. |
| `Failed: the bounds need 5,000,000 cells: …` | The bounds are too large for a grid at this cell size. Raise Cell Size or shrink the bounds. |

## From C++ and C#

### Bake again, or rebake a box

After moving or adding geometry from code, ask for a whole bake, or rebake only the tiles under the box the change covers. `MarkDirty` reads X and Z only: a tile spans every height. Both calls take the surface's entity. `RequestBake` returns false when the entity has no Navigation Surface; `MarkDirty` returns false when it has none in Mesh mode, since a grid rebakes through `RequestBake` only.

:::::tabs
::::tab[C++]

```cpp title="PathfindingECS/NavigationScriptApi.h"
bool RequestBake(ECS::World& world, ECS::EntityHandle surface);
bool MarkDirty(ECS::World& world, ECS::EntityHandle surface, Mathematics::Vector3 min, Mathematics::Vector3 max);
```

::::
::::tab[C#]

```csharp title="GameEngine.Scripting.Bindings"

public bool MarkDirty(Vector3 min, Vector3 max); // surface.Navigation.MarkDirty(min, max)
```

::::
:::::

```cpp title="Rebake the ground under a wall a player built"
#include "PathfindingECS/NavigationScriptApi.h"

GameEngine::Navigation::MarkDirty(world, surfaceEntity, wallMin, wallMax);
```

The tiles join the surface's queue on the next frame, also while the surface is still baking or loading its saved tiles, and rebake as [Rebaking what changed](#rebaking-what-changed) describes. Terrain edits and carving obstacles need no call.

### Size a bake before it runs

To show your own progress or refuse a bake that would be too large, read the box a surface covers and what a bake of it makes: mesh tiles in Mesh mode, grid cells in Grid mode. The count is the one the bake uses, so it matches the notice's "Baking: N of M" total.

```cpp title="Size a bake before it runs"
#include "PathfindingECS/Navigation.h"

GameEngine::Mathematics::Vector3 min, max;
if (GameEngine::Navigation::SurfaceBounds(world, surfaceEntity, min, max))
{
    const auto* surface = world.GetComponent<GameEngine::Components::NavigationSurface>(surfaceEntity);
    const uint64 units = GameEngine::Navigation::BakeUnitCount(*surface, min, max);
}
```

With Fit Bounds on and no terrain, `SurfaceBounds` gathers everything the bake reads to find the box: call it when the scene changes, not every frame.

### Find a path

A path query runs against the surface's map with its agent:

```cpp title="Find a path on a surface"
#include "Components/Navigation/NavigationSurface.h"
#include "PathfindingECS/NavigationService.h"
#include "PathfindingECS/NavigationSurfaceRuntime.h"
#include "Pathfinding/NavigationWorld.h"

using namespace GameEngine;

const auto* surface = world.GetComponent<Components::NavigationSurface>(surfaceEntity);
if (!surface || surface->BakePhase != Components::NavigationBakePhase::Baked)
    return;

Pathfinding::PathRequest request;
request.StartX = from.x; request.StartY = from.y; request.StartZ = from.z;
request.EndX = to.x;     request.EndY = to.y;     request.EndZ = to.z;
request.AgentRadius = surface->AgentRadius;
request.AgentHeight = surface->AgentHeight;

auto& navigation = PathfindingECS::NavigationService::Get();
Pathfinding::PathHandle path;
const auto map = PathfindingECS::ResolveNavigationSurfaceMap(world, *surface);
if (navigation.FindPath(map, request, path) == Pathfinding::PathStatus::Complete)
{
    auto& points = navigation.GetPathBuffer();
    for (uint32 i = 0; i < points.GetPointCount(path); ++i)
        Walk(points.GetPoint(path, i)); // the path's corners, start to end
}
if (path.IsValid())
    navigation.GetPathBuffer().FreePath(path);
```

`Partial` ends at the reachable point nearest the destination. `Failed` means the start or the destination has no walkable ground near it, or nothing connects them. The map handle stays the same across bakes in one Mode; changing Mode bakes into a new map with a new handle, so read it again after the bake. A [Navigation Agent](navigation-agent.mdx) needs no handle: it names its surface entity, and follows the surface across bakes and Mode changes.

### From the debug port

The editor's `find_path` tool answers the same query: `node mcp/ge.mjs find_path --from "[-400,20,-400]" --to "[400,33,400]"`. `get_navigation_stats` lists each surface's tiles: declared, resident, dirty, baking, stale, and built. `node mcp/ge.mjs raw mark_navigation_dirty '{"min":[0,0,0],"max":[30,0,30]}'` calls `MarkDirty`.
