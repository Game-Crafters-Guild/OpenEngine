A particle effect is three things on an entity: a **Particle Emitter** that decides when and how fast its particles simulate, the **processor stack** asset the emitter runs, which says what the particles do, and an optional **Particle Renderer** that says how they draw. Stacks are assets: one stack can drive any number of emitters, and editing it changes every emitter that runs it. This guide covers the components and the editor. The stack itself, its processors, and its file format are in [Particle processor stacks](particle-processor-stack.mdx).

## Making an emitter

- **Hierarchy, Create, Particle Emitter** makes an entity with an emitter. In a 2D Scene View the emitter is a 2D one: its particles stay on the entity's XY plane.
- **Add Component, Rendering** offers **Particle Emitter 2D**, **Particle Emitter 3D**, and **Particle Renderer** for an existing entity.

A new emitter runs the default stack: particles launched upward in a cone, at a rate of its **Amount** per second, falling under gravity. Press **New Stack** in its Processor Stack section to get a stack asset of your own: the editor writes `Particles/Particle Stack.particlestack` (numbered if the name is taken) into the project, starting from the default stack, and points the emitter at it. That step is one undo. To share a stack, drag the same asset onto several emitters' **Stack** field.

:::note

Without a Particle Renderer an emitter draws soft, procedural smoke puffs facing the camera, which is enough to see what a stack does. Add a Particle Renderer to choose the material, texture sheet, lighting, meshes, and trails. Switching the renderer off hides the particles. They keep simulating. Hundreds of overlapping puffs add up: the web seed project's smoke reads as a translucent gray plume with a mid-gray color (0.55), an opacity that peaks at 0.35 and thins as the column rises, and a size that grows along an S-curve, where full white at full opacity would draw an opaque white mass.

:::

## The emitter

| Field | Default | What it does |
|---|---|---|
| Stack | none | The processor stack asset the particles run. None runs the default stack. |
| Emitting | on | Off stops new particles; the ones alive keep simulating until they die. |
| Amount | 8 | The most particles alive at once, at most 4096. |
| Prewarm Seconds | 0 | Seconds simulated before the effect is first shown, at most 60. The effect appears when its prewarm finishes, spread over the first frames so no frame stalls. |
| Simulation Speed | 1 | Multiplies the simulation clock; 0 freezes the effect. |
| Dimension | World3D | World2D keeps particles on the emitter's XY plane. |
| Local Space | off | On, particles move with the emitter; off, they stay where they were born. |
| Ticks Per Second | 30 | Fixed simulation steps per second, up to 240. At 0 the simulation takes one bounded step per frame, which gives up determinism across frame rates. |
| Interpolate | on | Draws particles between steps. Off shows each step as it lands: a stepped, hand-animated look. |
| Seed | 0 | The effect's random sequence. 0 derives one from the entity, so copies differ; any other value makes every emitter with it identical. |
| Sub-emitters | none | Four slots naming the emitters the stack's spawn rules send particles to (see below). |

A fixed tick rate makes an effect deterministic: the same seed, stack, transforms, and tick sequence produce the same particles, whatever the frame rate. When a frame takes long the simulation runs at most eight ticks and drops the rest of the time, so a hitch slows the effect down rather than stalling the frame.

A moving emitter is where it was when each tick ended, between the transforms of the frames around it: it moves in a straight line, turns at a steady rate, and scales evenly between them. The particles a tick emits spread along the stretch it covered during the tick, the newest at the emitter, so a fast emitter lays an even trail, the same at any frame rate, and a spinning one keeps its shape. A move of more than 50 times the emitter's own scale in one frame is a teleport: that frame's particles start at the new place and the emitter is at rest there. To jump a shorter distance without a trail, restart the emitter.

### Previewing

The top of the emitter's inspector previews the effect in the Scene View: **Restart**, **Pause** (then **Play**), **Step** one tick, and **Preview Time**, which scrubs the effect to a time between 0 and 60 seconds and pauses it there. Scrubbing replays the effect at the emitter's current transform in small chunks over the next frames. It raises no collision events and sends nothing to sub-emitters. The card below the buttons shows the live particle count, the preview time, the simulation cost, and dropped time. The first preview action adds a **ParticlePlayback** component to the entity to carry these commands. It is runtime state and is not saved with the scene.

### Sub-emitters

A stack's spawn rules (the Event processor's *Spawn in Child Emitter* action) name one of four slots, **Sub-emitter 1** to **Sub-emitter 4**. The emitter's Sub-emitters section says which entity each slot is. The child receives the particles on its next update, at the parent particle's world position, carrying what the rule says it inherits (velocity, size, color, rotation, lifetime). A child emitter whose stack emits nothing on its own shows only what its parents send it. A slot that names no emitter, or a switched-off one, drops the spawns. Scene files keep the slots pointing at the entities they name.

### Events from gameplay

A stack reacts to named events a game sends to its emitter through the Event processor's *On Game Event* trigger. Send one through the emitter's `ParticlePlayback`:

```cpp title="Send a game event to an emitter"
#include "Components/Rendering/Particles.h"
#include "Types/StringId.h"

void Detonate(ECS::World& world, ECS::EntityHandle emitter)
{
    if (!world.HasComponent<Components::ParticlePlayback>(emitter))
        world.AddComponentImmediate(emitter, Components::ParticlePlayback{});
    world.GetComponentForWrite<Components::ParticlePlayback>(emitter)->SendEvent("Detonate"_sid);
}
```

Every live particle of the emitter runs its game-event rules for that name on the emitter's next update. Up to eight events wait per update. `SendEvent` returns false when the queue is full. The same component restarts (`++Restart`), pauses (`Paused = true`), and steps (`++SingleStep`) the effect from gameplay code.

### Collision events

The stack's Collision processor bounces particles off a plane or off the physics world. To read the collisions in gameplay code, add **Particle Collision Events** (Add Component, Rendering) to the emitter, or to any one entity for every emitter that has none: its `ParticleCollisionEventsBuffer` holds the frame's first 64 contacts, each with the emitter, the particle, the position, normal, velocity, and whether the particle died.

## The renderer

The Particle Renderer's inspector groups its fields by what they change and shows the six-way, emitter-scale and trail rows only when they apply.

### Material and texture sheet

**Material** is optional: a material asset whose properties and textures the particles use. The particle shaders, blending, and lighting mode always come from the renderer. The material's own surface shader or graph is not used. Without one, particles use a neutral material in which the particle color alone sets the color. **Texture** is an RGBA atlas whose cells count left to right, then top to bottom. Every sample stays half a texel inside its cell. Leave gutters between cells if the atlas is viewed small enough to reach lower mip levels.

| Field | What it does |
|---|---|
| Columns, Rows | The atlas grid, 1 to 256 each. |
| Frame Count | Cells the sheet plays; 0 plays every cell. |
| Frame Rate | Playback rate in frames per second. At 0 the sheet plays once over each particle's life. The simulation speed also scales it; a stack can vary it per particle with the Animation Speed and Animation Offset attributes. |
| Start Frame | The first cell, fractional when blending. |
| Loop | Loop when playing at a frame rate. |
| Blend Frames | Crossfade between neighboring cells, including the last-to-first seam when looping. Turn it off for hand-drawn frames that must not blur into each other. |

### Lighting

**Unlit** draws the authored color relative to the camera's exposure: a color of 1 draws as the display's white at whatever exposure the view has, so unlit smoke authored gray reads gray in daylight and at night alike. **Lit** lights particles as a uniform volume from the scene's lights and environment: directional, point, spot, and area lights, their shadows, and the ambient probe. There is no flat-surface cosine or specular highlight. **SixWay** lights them from six baked directional response maps, which gives smoke and fire volume under moving lights. Assign **Six Way Map A** and **Six Way Map B** and pick how they pack the six directions:

| Six Way Layout | Map A | Map B | Opacity | Emission mask |
|---|---|---|---|---|
| SignedAxes | +X, +Y, +Z | −X, −Y, −Z | Texture alpha | Emission Texture |
| RightTopBackRgba | right, top, back, opacity | left, bottom, front, emission | Map A alpha | Map B alpha |
| TopLeftRightBottomBackFront | top, left, right | bottom, back, front | Texture alpha | Emission Texture |

Directions are in the sprite's own basis: right, up, and toward the camera as front. Import the maps as linear data unless the pack says otherwise. The renderer samples the color space the texture asset declares. The maps play on the same grid and frame as the texture sheet. **Six Way Contrast** raises the response to a power, which firms up maps baked with a soft response; 1 keeps them as baked. Until both maps are assigned the particles light as **Lit**, and the inspector says so.

**Emission Color** and **Emission Intensity** make the particles glow with their own light, which shows with scene lights off but does not light other objects. An intensity of 0 emits nothing. On **Unlit** particles the emission is relative to the exposure like the color: an intensity of 1 adds the display's white. On **Lit** and **SixWay** particles it is scene light, where 1 is the engine's reference white of 203 nits, so a glow meant to show in daylight needs an intensity in the hundreds. Without an emission texture the whole particle glows. **Emission Texture** says where it glows: an RGB emissive atlas played with the sheet (for fire inside smoke), which replaces map B's emission alpha when the RGBA layout is used. To light the scene, give the stack a Light processor.

### Orientation and order

| Billboard | The quad or mesh |
|---|---|
| FaceCameraPosition (default) | Faces the camera's position rather than its plane, so particles near the screen edges turn toward the viewer. A particle close to the camera covers the part of the view it fills, not the whole width a quad parallel to the camera plane spreads over at a wide field of view: with the camera inside a smoke column this draws about 40 % fewer fragments. |
| FaceCamera | Faces the camera plane. |
| WorldOriented | Keeps the emitter's plane; rotate the entity to orient it. Six-way lighting keeps its signed axes from behind. |
| LockedToEmitterUp | Turns toward the camera around the emitter's up axis, like a tree sprite. |
| Horizontal | Lies flat, facing up. |
| YAlongVelocity | Its up axis follows the velocity in 3D. |
| FaceCameraYAlongVelocity | Faces the camera with its up axis along the velocity as seen on screen: the stretched spark. |
| ZAlongVelocity | A mesh's forward axis follows its actual motion, including motion from noise. |

**Inherit Scale** makes the particles take the emitter's scale on top of their own size, in every billboard mode. **Velocity Stretch** lengthens particles along their motion by that much per unit of speed. **Draw Order** sorts particles back to front. **ViewDepth**, the default, sorts every particle by its own distance from the camera, across emitters, so a column of smoke reads right from above and from below. **Spawn** (the newest on top), **Lifetime** (the oldest on top), and **ReverseLifetime** (the youngest on top) keep an emitter's particles together in that order and place the emitter by the depth of its origin, which suits effects seen from one side. Particles draw after opaque geometry, blended, without writing depth. They receive shadows and do not cast them.

### Meshes

Assign up to four models to **Meshes** to draw each particle as those meshes (the first submesh of each, unskinned) instead of a sprite. Every assigned mesh draws for every particle. With none, particles are sprites.

### Trails

When the stack has a Trail processor, the renderer draws each particle's recorded path as a ribbon facing the camera. **Trail Only** hides the particles and keeps the ribbons (tracers, streaks). **Trail Inherit Color** tints a trail with its particle's color instead of white. **Trail Size Affects Width** makes the width follow the particle's size. **Trail Fade Over Length** fades toward both ends rather than over the points' age. **Trail Width Min** and **Max** pick a width multiplier once per trail, **Trail Alpha Peak** is the opacity at its most opaque point, and **Trail Texture Tile** repeats the texture by distance traveled (**Trail Texture Scale U**, **V**) instead of stretching it over the trail.

### Visibility

**Render Layers** chooses the views that draw the particles, as for meshes. A scene saves it as layer numbers in brackets, for example `ParticleRenderer.RenderLayers = [0, 2]`. **Thinning Start** and **Thinning End** hide a growing share of the particles between the two distances from the camera in meters, the same particles every frame, and all of them beyond the end. An end distance of 0 turns thinning off, and the inspector says so. Culling and thinning never pause the simulation.

A sprite that faces the camera (**FaceCamera** or **FaceCameraPosition**, not stretched by **Velocity Stretch**) fades out before the camera's near plane can cut it. Its opacity falls from full to nothing while its distance from the camera comes from two of its half-diagonals to one half-diagonal past the near plane, and closer than that it is not drawn. Both distances stop at 3 m and 1.5 m, so a large sprite seen from outside is drawn until the camera is close. The distance is measured to the camera, not along the view, so a cloud does not thin as the camera turns. With the camera inside a smoke column, the puffs around the camera are not drawn. Under an additive or other authored blend the color and emission fade too, as the square of the fade, so a bright glow dims across the whole distance rather than at its end. Ground-aligned and world-oriented sprites, sprites on an emitter with Velocity Stretch, meshes, and trails do not fade.

## Budgets

An emitter simulates at most its Amount, up to 4096 live particles. A world simulates at most 65,536 by default. Add a **Particle World Settings** component to set a lower **Max Particles** (the lowest wins when there are several). Emitters take their share in entity order, so the same scene always spends its budget the same way. The simulation runs on the CPU, one emitter after another, in the frame's extraction phase. It needs a world transform but no camera or graphics device, so it runs in headless worlds and tests too.

## Packaging

Stacks are written as JSON in the project so they diff and merge. When a game is built, the build cooks every stack it packages into a compact binary form the Player reads without parsing JSON. A stack that fails to cook fails the build with its path and the reason. Nothing needs setting up.

A browser has no shader compiler, so a web export cooks the particle shader programs ahead of time: for each kind of particle material (lighting mode, six-way layout, texture sheet, and emission texture), the programs the render pipeline draws particles with. Those are the keywords of the pipeline's **Transmissive** node that particles take (ForwardPlus and Shadows, with or without IBL), on a sprite or on a mesh with or without tangents. The engine's own pipelines are covered. A project pipeline whose Transmissive node has other keywords, or a mesh particle whose mesh brings vertex colors, extra UV sets, or skinning, has no cooked program on the web. The emitter then does not draw, and the browser console reports "no cooked program" with the material's name and its defines. To fix it, give the Transmissive node ForwardPlus, Instanced, and Shadows (IBL optional), and use meshes without those extra streams.

## Limits

- **CPU simulation.** Particles simulate on the CPU. There is no GPU simulation path.
- **Tick-aligned timing.** Processor intervals and age triggers take effect at simulation ticks, so at 30 ticks per second an interval starts within a thirtieth of a second of its time.
- **Physics collisions** sweep a ray extended by the particle's radius rather than a sphere, and can miss glancing contacts. Without a physics world they find nothing.
- **Particle lights** are capped at 64 per frame across the world.
- **No self-shadowing.** Particles receive scene shadows but cast none.
